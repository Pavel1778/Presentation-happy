# 2026-10-08 — Session: Cyrillic metrics + content audit + rebuild (Presentation-happy)

## Root cause of bad Russian text layout in the native PPTX
- `svg_to_pptx/drawingml/font_advances.json` shipped WITHOUT Cyrillic glyphs
  (`has cyr А: False`). The DrawingML exporter measures text width from this
  table, so every Russian string was measured too short -> wrong wraps/overflow.
- Fix: `/tmp/add_cyrillic.py` adds Cyrillic advances from metric-compatible
  Liberation fonts (Arial<->Liberation Sans, Times<->Liberation Serif) via PIL
  `ImageFont.getlength`. 36 styles updated; file grew to ~10640 lines.
  Verified: "Выводы и источники" 48 bold -> 508.1px matches the exporter mеtr.
- Measurement helper convention: `advance = ImageFont.truetype(font, sz).getlength(t)`;
  compare `*1.12` against the container width as the wrapping safety margin.

## Quality gates that caught real issues
- `svg_quality_checker --canonical-authoring --stage final`: two failure modes
  to watch — (a) text CONTENT bbox exceeding a group's `data-pptx-bounds`
  (vertical/horizontal %, error above 5%), (b) sibling top-level module zones
  overlapping. Fix by expanding the owning group's band, and keep ADJACENT
  bands disjoint: if an overflow warning sits next to a neighbor band, growing
  down can create an overlap error (saw p11-findings/p11-credits).
- `pdftotext -bbox` is a great independent overlap/edge detector on the rendered
  PDF (0 overlaps, 0 page-frame overflow after fixes).
- QR verification: crop the QR from a `pdftoppm` render and decode with
  `cv2.QRCodeDetector` (`pip install opencv-python-headless`; installs fine).
  Decoded `https://github.com/Pavel1778/Presentation-happy#полный-список-источников`
  -> keep the README heading anchor stable.
